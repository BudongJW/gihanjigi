# 배포

기한지기 시제품은 Vercel 에 올린다(의뢰인 결정, 2026-10-09). 배포는 건마다 의뢰인 승인을 받고, 승인받은 사람이
GitHub Actions 의 `deploy` 워크플로를 손으로 돌릴 때만 일어난다.

## 무엇을 올리나

- `src/` 를 빌드 없이 그대로 올린다. 화면과 계산 엔진은 의존성이 없어서 설치와 빌드 단계가 없다.
- `vercel.json` 이 설정을 정한다. 출력 폴더는 `src`, 설치와 빌드 명령은 비워 두었다.
- 모든 주소에 보안 헤더 넷을 붙인다.

| 헤더 | 값 | 까닭 |
|---|---|---|
| Content-Security-Policy | `frame-ancestors 'none'` | 다른 사이트가 시제품을 틀 안에 넣어 속이지 못하게 한다. 페이지의 CSP 메타 태그로는 이 지시를 걸 수 없다 |
| X-Content-Type-Options | `nosniff` | 브라우저가 파일 형식을 짐작하지 않게 한다 |
| Referrer-Policy | `no-referrer` | 근거 조문 링크를 누를 때 시제품 주소를 넘기지 않는다 |
| Permissions-Policy | `camera=(), microphone=(), geolocation=()` | 쓰지 않는 기기 권한을 막는다 |

- 페이지의 CSP 메타 태그(`connect-src 'none'`, `form-action 'none'`)와 `noindex` 메타 태그는 그대로 둔다. 헤더의
  CSP 는 메타 태그의 정책에 더해진다.
- `vercel.json` 의 `git.deploymentEnabled` 를 `false` 로 두었다. 누가 이 저장소를 Vercel 에 연결해도 푸시나 PR 마다
  저절로 배포되지 않는다.
- 2026-10-09에 Vercel CLI 59.26.0 으로 계정 없이 `vercel build --prod` 를 돌려 확인했다. 결과물의 정적 파일은
  `src` 와 같았고, 헤더 넷이 모든 경로에 붙었다. 같은 헤더를 로컬 서버에 붙여 `npm run check:browser` 도
  통과했다.

## 처음 한 번 할 일

계정과 토큰을 만드는 일이라 의뢰인이 직접 한다.

1. Vercel 계정을 만든다. 무료 Hobby 요금제는 약관상 개인의 비상업 용도로만 쓸 수 있다. 공모전에 내는 창업
   시제품이 여기에 맞는지는 의뢰인이 판단한다. 맞지 않으면 Pro 요금제를 쓴다.
2. 저장소 클론에서 프로젝트를 만들고 연결한다.

       npx vercel@59.26.0 login
       npx vercel@59.26.0 project add gihanjigi
       npx vercel@59.26.0 link --yes --project gihanjigi

   `link` 가 `.vercel/project.json` 에 `orgId` 와 `projectId` 를 적는다. `.vercel/` 은 커밋하지 않는다
   (`.gitignore` 에 넣었다).
3. Vercel 대시보드의 Account Settings > Tokens 에서 토큰을 만든다. 범위는 이 프로젝트가 있는 계정으로 하고
   만료일을 둔다.
4. GitHub 저장소의 Settings > Secrets and variables > Actions 에 시크릿 셋을 넣는다.

   | 이름 | 값 |
   |---|---|
   | `VERCEL_TOKEN` | 3에서 만든 토큰 |
   | `VERCEL_ORG_ID` | `.vercel/project.json` 의 `orgId` |
   | `VERCEL_PROJECT_ID` | `.vercel/project.json` 의 `projectId` |

토큰은 채팅이나 커밋에 붙이지 않고 GitHub 시크릿에만 넣는다.

## 배포할 때

1. 의뢰인 승인을 받는다.
2. GitHub 의 Actions > deploy > Run workflow 에서 `main` 을 고르고 돌린다. `main` 이 아니면 돌지 않는다.
3. 워크플로는 시크릿이 있는지 보고, `npm run verify` 를 통과한 뒤에만 올린다. 올린 주소는 실행 요약에 남는다.
4. 배포한 뒤 production 주소(gihanjigi.vercel.app, 그 주소를 이미 누가 쓰면 뒤에 글자가 붙는다)를
   열어 본다. 화면이 뜨는지, 브라우저 콘솔에 오류가 없는지, 기한 화면의 근거 링크가 국가법령정보센터로 가는지
   본다. `?today=2026-10-09` 를 붙이면 기준일을 고정해서 볼 수 있다.

새 프로젝트는 기본 설정에서 배포마다 붙는 주소를 Vercel 로그인 뒤에 두고 production 주소만 공개한다. 심사위원이나 인터뷰 대상자에게는
production 주소를 준다.

## 되돌리기

Vercel 대시보드의 Deployments 에서 이전 배포를 골라 production 으로 되돌린다(Instant Rollback). 되돌리는 것도
배포라서 의뢰인 승인을 받는다.
